# 보고서 형식

요청한 문서의 목적에 맞는 형식만 사용한다. 빈 항목을 억지로 채우지 말고, 확보하지 못한 정보는 `미확인`으로 표시한다.

## 보안 진단 보고서

1. 요약: 대상·범위·기준 시점, 주요 위험과 우선 조치.
2. 방법: 사용한 분석 방식, 실행 환경, 재현 범위 및 제한.
3. 발견 사항: 식별자, 상태(`확인됨`/`가능성 있음`/`근거 부족`/`오탐`), 심각도와 확신도, 영향받는 위치·조건, 입력에서 위험 동작까지의 근거, 영향, 재현 또는 반증 결과, 권장 조치와 재검증 방법.
4. 검증 결과: 실행 명령과 결과, 미실행 항목, 남은 불확실성.

## 기술 포트폴리오

1. 프로젝트 맥락: 해결하려는 문제, 대상 사용자, 본인 역할과 작업 범위.
2. 설계: 모듈 경계, 핵심 선택과 그 이유, 보안상 고려한 신뢰 경계.
3. 구현: 본인이 만든 기능과 확인 가능한 코드·변경 근거.
4. 검증: 테스트 방법, 데이터셋 범위, 결과와 실패·개선 사례. 탐지 지표에는 표본 수와 계산 기준을 붙인다.
5. 회고: 현재 한계와 다음 개선 과제. 완료하지 않은 작업은 성과로 표현하지 않는다.
