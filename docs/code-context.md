# 코드 문맥 추출 계약 (Phase 2A)

`extract_code_context(target_root, finding, policy, end_line=None)`은 기존 `Finding`이 가리키는 프로젝트 상대 파일에서 제한된 줄 범위를 읽는다. `Finding`에는 시작 줄만 있으므로 종료 줄을 신뢰할 수 있게 얻은 경우에만 `end_line`을 별도 전달한다. 지정하지 않으면 단일 줄 탐지로 취급한다. 함수·메서드 경계나 호출 관계를 추정하지 않는다.

반환값 `InternalCodeContext`는 두 부분으로 분리된다.

- `metadata: CodeContext`: Finding ID, 대상 루트의 해시 식별자, 프로젝트 상대 경로, 탐지 및 추출 줄 범위, 규칙 ID, 상태, 마스킹·절단·생략 여부, 고정 issue 코드와 한계. `public_report()`와 `CodeContext.model_dump(mode="json")`에는 코드 원문이 없다.
- `lines: tuple[UntrustedCodeLine, ...]`: 줄 번호가 붙은 **비신뢰 소스 데이터**. 값은 마스킹 후 내부에서만 사용하며 공개 보고서나 기존 `scan` JSON에 자동 추가하지 않는다. 파일에서 읽은 원본 바이트와 디코딩 문자열은 함수의 지역 변수로만 사용한다. 메모리 내 원본 버퍼의 즉시 삭제는 보장하지 않는다.

상태는 `available`, `redacted`, `truncated`, `unavailable`이다. `truncated` 상태에서도 `redacted=true`일 수 있으므로 플래그를 함께 확인한다. `omitted=true`는 파일 전체가 수집되지 않았음을 뜻한다. 실패 시 줄 목록은 비어 있고 issue는 소스 내용이 아닌 고정 코드다. 방어 로직을 탐색하지 않으므로 **“현재 수집 범위에서 확인되지 않음”**을 부재 판정으로 사용하지 않는다.

## 읽기 경계

- `.`·`..`, 절대 경로, 백슬래시, 제어 문자가 있는 경로를 거부한다. `.git`, `node_modules`, 생성 캐시, `.env*`, 자격 증명으로 보이는 이름과 키 파일을 제외한다.
- 루트에서 각 경로 성분을 디렉터리 디스크립터와 `O_NOFOLLOW`로 열어 심볼릭 링크를 따르지 않는다. 최종 파일을 연 뒤 `fstat`으로 일반 파일 여부를 확인하고 하드 링크 수가 1이 아니면 거부한다. 읽기는 열린 디스크립터에서 수행하므로 확인 뒤 경로가 교체되어도 다른 경로를 다시 열지 않는다. 이 보장은 호스트 OS의 파일 디스크립터 동작에 의존하며, 대상 루트의 상위 경로가 공격자에게 재지정될 수 있는 환경의 격리를 대신하지 않는다.
- 기본 상한: 파일 1 MB, 탐지 전후 각 3줄, 전체 15줄, 결과 8 KB, 한 줄 2 KB. 정책으로 줄일 수 있고 각 상한에는 하드 제한이 있다. UTF-8 텍스트만 수용하며 NUL 바이트와 잘못된 인코딩은 거부한다. 탐지 줄이 너무 길거나 탐지 범위가 한도를 넘으면 문맥을 반환하지 않는다. 주변의 긴 줄은 표시자로 대체하고 `truncated`로 표시한다.

명시적으로 확장 문맥이 필요할 때만 별도 `extract_expanded_code_context()` API를 사용한다. 기본 동작, CLI 및 공개 scan JSON에는 연결되지 않는다. 언어 지원, 상한, fallback, sparse line citation 및 한계는 [확장 코드 문맥 계약](expanded-code-context.md)에 정의한다.

## 마스킹과 신뢰 경계

API Key·Token·Password 등 민감 단어, 알려진 토큰 형식, 이메일 후보가 있는 줄은 줄 전체를 가린다. 여러 줄 대입, 개인키 헤더, 긴 불투명 문자열처럼 안전한 마스킹을 확신하기 어려우면 `redaction_uncertain`으로 문맥 전체를 반환하지 않는다. 정규식 기반 감지는 모든 비밀·개인정보를 찾지 못하며, 가려진 코드는 원래 의미와 달라질 수 있다. 따라서 마스킹된 줄도 외부 전송을 승인한 자료로 간주하지 않는다.

소스 코드와 주석은 `untrusted_source_code`로 표시한다. 주석의 명령형 문구는 텍스트 데이터일 뿐이다. 이 모듈은 프롬프트를 만들거나 LLM을 호출하지 않는다. Phase 2B에서는 신뢰된 분석 지침과 이 데이터를 별도 필드로 유지하고, 전송 전 목적·범위·민감정보 검토 및 격리 정책을 별도로 정의해야 한다. 단순 문자열 필터링만으로 프롬프트 인젝션이 차단되지는 않는다.
