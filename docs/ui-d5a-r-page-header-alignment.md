# UI-D5A-R — 좁은 화면 페이지 헤더 정렬

## 변경 내용

1024px 이하에서 페이지 제목과 설명이 한 줄에 남거나 오른쪽으로 밀리던 문제를 공통 페이지 헤더 규칙으로 수정했다. 원인은 `.workspace-title`이 `justify-content: space-between`인 가로 Flex 레이아웃을 유지한 채, 서로 다른 CSS 선택자와 미디어쿼리에서 정렬만 바꾸고 있던 점이다. 모바일에서는 `.ui-d2 .workspace-title` 규칙이 낮은 우선순위의 왼쪽 정렬을 덮어썼다.

`frontend/src/app-shell-d5a.css`에 1100px 이하 공통 규칙을 추가했다. 제목과 설명을 세로로 쌓고, 양쪽 모두 왼쪽 정렬하며, 설명의 데스크톱용 왼쪽 구분선과 들여쓰기를 제거했다. 기존 폰트 크기, 넓은 화면의 오른쪽 설명 배치, 사이드바와 콘텐츠 구조는 유지했다. 임의의 여백이나 절대 위치 지정은 사용하지 않았다.

## 좌표 측정

Playwright Chromium에서 실제 DOM bounding box를 측정했다. X좌표는 CSS 픽셀 기준이다.

| Viewport | 화면 | 수정 전 제목 / 설명 / 주요 콘텐츠 X | 수정 후 제목 / 설명 / 주요 콘텐츠 X |
| --- | --- | --- | --- |
| 1920×1080 | 검사 시작 | 324 / 1513 / 324 | 324 / 1513 / 324 |
| 1440×900 | 검사 시작 | 315 / 1042 / 315 | 315 / 1042 / 315 |
| 1024×768 | 검사 시작 | 304 / 637 / 304 | 304 / 304 / 304 |
| 768×1024 | 검사 시작 | 272 / 272 / 272 | 272 / 272 / 272 |
| 600×800 | 검사 시작 | 369 / 281 / 18 | 18 / 18 / 18 |
| 390×844 | 검사 시작 | 193 / 71 / 18 | 18 / 18 / 18 |
| 320×800 | 검사 시작 | 123 / 18 / 18 | 18 / 18 / 18 |

검사 결과와 사용 안내 화면도 1024, 768, 600, 390, 320px에서 제목·설명 왼쪽 정렬 및 가로 넘침을 확인했다. 좁은 화면에서 제목과 설명의 X좌표가 일치했고, 시작 화면은 각 페이지 주요 콘텐츠와 같은 X좌표에서 시작했다. 모든 지정 viewport에서 문서 가로 넘침은 0px였다.

## 시각 자료

동일한 합성 API 응답을 사용했다. 합성 프로젝트는 검수용이며 실제 검사 결과가 아니다.

- 검사 시작 Before/After: [스크린샷 폴더](assets/ui-d5a-r/)
- 검사 결과와 사용 안내: `before-results-*`, `after-results-*`, `before-guide-*`, `after-guide-*`
- 지정 viewport 검사 시작: `before-start-*`, `after-start-*`

Before는 UI-D5A의 기존 CSS로 빌드해 캡처했고, After는 새 반응형 규칙으로 다시 빌드해 캡처했다. Chromium 캡처이며 실제 Safari 렌더링 검수는 수행하지 않았다.

## 검증

- TypeScript: `npm run typecheck` 통과.
- Production build: `npm run build` 통과.
- Vitest: 4개 파일, 44개 테스트 통과.
- Chromium Playwright 전체: 20개 테스트 통과.
- 전용 브라우저 회귀 테스트는 검사 시작·검사 결과·사용 안내를 순회하고 1920×1080, 1440×900, 1024×768, 768×1024, 600×800, 390×844, 320×800에서 위치와 가로 넘침을 검사한다.
- 760px 이하에서 모바일 탐색을 열고 Escape로 닫는 동작도 확인한다.
- 실제 Safari는 이 환경에서 자동 제어하지 않았으므로 사용자 수동 확인은 별도다.

## 범위와 보존

변경은 공통 페이지 제목의 반응형 정렬에 한정했다. 검사 기능, 토큰 처리, API 계약, 결과 화면 콘텐츠, 사이버펑크 테마 및 기존 큰 글씨는 수정하지 않았다. 기존 미커밋 파일과 다른 Phase 자료는 스테이징하지 않는다.
