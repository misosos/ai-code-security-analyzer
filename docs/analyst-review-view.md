# 분석가 검토 화면

## 목적과 사용법

Review View는 Semgrep이 보고한 검토 후보와 현재 구조적 근거의 범위를 사람이 확인할 수 있도록 표시합니다. 취약점 판정, 자동 확인 기록, LLM 호출은 하지 않습니다.

```sh
uv run python -m ai_code_security_analyzer scan \
  --path /path/to/project \
  --rules rules/security-baseline.yml \
  --format review
```

기존 `text`와 `json` 형식은 유지됩니다. `--output`은 JSON 전용이며 review 파일 저장은 지원하지 않습니다. review를 선택하면 Adapter의 내부 결과 경로에서 Finding과 TaintEvidence를 함께 받아 Semgrep을 한 번 실행합니다.

예시 형식(내용은 합성 예시):

```text
검토용 분석 결과
검사 상태: 정상 완료
검사 완료: 예
검토 대상: 1건 (취약점 확정 수가 아님)

검토 대상 #1 (표시 순서이며 위험 순위가 아님)
요약: taint 규칙 매치 검토
Semgrep 심각도 분류: high (실제 악용 가능성 판정은 아님)
검증 상태: 미검증 후보 (취약점·오탐 모두 미확정)
탐지 유형: taint 규칙 (정의된 입력 흐름을 검사하는 규칙)
확인된 사실:
- Semgrep이 신뢰된 taint 규칙에 따른 매치를 보고했습니다.
확인되지 않았거나 이 분석에서 지원하지 않는 내용:
- 확인 항목: 전체 데이터 흐름 경로 제공 [현재 자료에서 확인 불가]
분석가 검토 항목:
1. 실제 입력 출처를 코드에서 확인
```

## 화면 구성과 해석

Scan Overview는 검사 상태·완료 여부·Semgrep 버전·검토 대상 수·심각도별 집계·안전하게 매핑한 검사 안내를 보여줍니다. Finding 수는 취약점 확정 수가 아닙니다. 완료된 0건 결과도 코드가 안전하다는 뜻이 아닙니다. 실패 또는 부분 검사에는 눈에 띄는 제한 안내를 붙입니다.

각 Finding 카드는 표시 순서 번호, 불투명 Finding ID, 규칙 ID, 도구 심각도 분류, 별도의 검증 상태, 탐지 유형과 Semgrep 결과의 상대 경로·줄을 표시합니다. 번호는 위험 순위가 아닙니다. severity는 도구의 분류이며 실제 악용 가능성을 뜻하지 않습니다. `unverified` 상태는 취약점과 오탐 어느 쪽도 확정되지 않은 검토 후보를 뜻합니다. 상대 경로는 기존 Finding에서 왔으며, 안전하지 않은 경로와 식별자는 숨깁니다. 원본 코드, snippet, Finding 설명·증거 텍스트와 Semgrep 자유 형식 메시지는 출력하지 않습니다.

근거 섹션은 `consume_evidence_summary()`를 통과한 claim만 “확인된 사실” 아래 표시합니다. 나머지는 decision과 고정 한국어 사유로 “확인되지 않았거나 이 분석에서 지원하지 않는 내용”에 표시합니다. claim 출처와 Gate 제한 코드에 기반한 해석 제한도 함께 보여줍니다. 내부 enum 문자열을 그대로 출력하지 않습니다.

예를 들어 taint 결과는 “Semgrep이 신뢰된 taint 규칙에 따른 매치를 보고했습니다” 및 규칙에 선언된 Source/Sink 패턴과 매치 위치를 표시할 수 있습니다. 반면 실제 Source 위치, Sink 인자 위치, 전체 Source→Sink trace, Sanitizer 매치·효과, 취약점 확정은 별도로 지원되지 않는 한 제한 항목으로 남습니다. 일반 pattern 결과는 taint 결과로 승격되지 않으며, 신뢰 규칙 해시나 연결이 검증되지 않으면 unclassified로 표시됩니다.

고정된 분석가 검토 항목은 다음으로 확인할 작업을 제안할 뿐입니다. 체크리스트 상태를 저장하거나 작업 완료·취약점 판정을 기록하지 않습니다. 구조화 trace가 제공되지 않았다는 문구는 흐름이 없다는 의미가 아닙니다.

## 상태·개인정보·제한

- `completed`는 검사가 정상 종료됐다는 뜻이며 안전성이나 취약점 부재를 뜻하지 않습니다.
- `partial`은 일부 경로·규칙 누락 가능성을 표시합니다. Gate가 지원하는 개별 관찰이 있어도 전체 검사 완료로 표시하지 않습니다.
- 실행 실패·timeout·잘못된 JSON·출력 제한·Semgrep 미설치 시 지원 근거를 확인 사실로 표시하지 않고 실패 경계를 드러냅니다.
- Consumer 검증 실패는 해당 카드의 사실을 비우고 고정 오류 코드로 표시합니다. 다른 카드의 근거는 재사용하지 않습니다.
- terminal 제어문자와 bidi format 문자는 escape 처리하며, 절대 경로·상위 경로·URL 형태 위치는 숨깁니다. 출력량은 Finding 수와 바이트 상한으로 제한하고 생략 건수 및 생략된 항목의 개별 검증 상태를 알 수 없음을 표시합니다.
- Finding은 계속 `unverified`이며 Severity는 확인 상태와 별도입니다.
- 현재 규칙 해시는 review 시 다시 검사하지만 Semgrep 실행 시점의 규칙 바이트와 원자적으로 동일했음을 증명하지 않습니다. 분석 대상 파일의 실행 시점 이후 불변성도 보장하지 않습니다.
- 도구는 OS 수준 네트워크 격리를 제공하지 않습니다. 신뢰할 수 없는 저장소는 별도 격리 환경에서 분석해야 합니다.

이 화면은 구조화된 근거의 가용성을 설명합니다. 인용·규칙 매치가 의미적으로 실제 취약점을 입증하는지는 분석가가 코드와 실행 조건을 따로 검토해야 합니다.
