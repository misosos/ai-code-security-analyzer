# Phase 8H — Safari 사용자 검수 실행 안내

이 안내는 실제 macOS Safari에서 제품을 검수하기 위한 절차다. Playwright WebKit 또는 Chromium 결과는 Safari 사용자 검수 결과를 대신하지 않는다. 이번 QA 서버는 임시로 만든 합성 프로젝트만 검사한다.

## 1. 사전 준비

검수 worktree는 다음 경로다.

```sh
cd /tmp/ai-csa-phase8h
```

필요한 도구와 버전을 확인한다.

```sh
node --version
npm --version
uv --version
semgrep --version
```

프런트엔드 `package.json`은 Node.js `>=24 <25`를 요구한다. 의존성이 아직 없다면 잠금 파일 기준으로 설치한다.

```sh
cd /tmp/ai-csa-phase8h/frontend
npm ci
```

Semgrep이 설치되지 않았거나 버전이 다르면 다음 명령으로 고정 버전을 설치한 다음 버전을 확인한다.

```sh
uv tool install --python 3.12 --force semgrep==1.182.1
export PATH="$(uv tool dir --bin):$PATH"
semgrep --version
```

출력 버전이 `1.182.1`이어야 한다. QA 실행 스크립트는 다른 Semgrep 버전이면 시작을 거부한다.

## 2. QA 서버 실행

프런트엔드 디렉터리에서 다음을 실행한다.

```sh
cd /tmp/ai-csa-phase8h/frontend
npm run qa:safari
```

실행할 때마다 서버 API 토큰과 두 개의 합성 프로젝트를 새로 만든다. API와 Vite는 동적 포트를 사용하고 `127.0.0.1`에만 바인딩한다. 터미널에 표시되는 접속 주소와 토큰을 확인한다.

- 접속 주소는 Safari 주소창에 입력한다.
- 토큰은 AI Code Security Analyzer 화면의 `로컬 API 토큰` 입력란에 입력한다.
- 토큰을 URL, 채팅, 문서, 메모 또는 스크린샷에 넣지 않는다.
- 서버 로그는 API 토큰을 출력하지 않는다. 토큰은 실행 중 API 프로세스 환경에서만 사용된다.
- QA 서버는 로그인 시 자동 실행되지 않는다. 검수 터미널을 닫거나 종료하면 서버를 정리한다.

## 3. 합성 프로젝트 A/B 확인

검사 대상은 다음 두 개만 서버 시작 시 등록된다.

| 대상 | 내용 | 기대 관찰 |
|---|---|---|
| Safari QA 합성 프로젝트 A | `stable.js`, `review.js`의 `eval` 예제 | Baseline 규칙으로 Finding 두 건 |
| Safari QA 합성 프로젝트 B | 입력을 문자열로 변환하는 안전 예제 | Finding 0건 |

코드는 실행되지 않고 Semgrep 정적 분석만 수행된다. B의 0건은 안전성 증명이 아니다. 브라우저에서 임의 경로를 입력하거나 파일을 수정하는 기능은 제공하지 않는다.

## 4. 권장 검수 순서

1. Safari에서 터미널의 `http://127.0.0.1:<동적 포트>` 주소를 연다.
2. API 연결 상태가 표시되는지 확인하고 생성된 토큰을 입력한다.
3. 대상 A와 `Baseline Rules`를 선택해 검사를 실행한다. 실제 Finding 두 건과 파일 위치를 확인한다.
4. 각 Finding을 선택하고 검토 상태를 다르게 설정한다. 예시 메모에는 실제 코드나 비밀정보를 적지 않는다.
5. 분석가 검토 Markdown을 다운로드한다. 메모 기본 제외를 확인하고, 메모를 포함하는 동작은 경고를 읽은 뒤 명시적으로 동의할 경우에만 수행한다.
6. JSON 백업을 다운로드한다. 메모 제외와 포함 동의를 각각 확인한다. 다운로드한 파일은 디스크에 남을 수 있다.
7. 대상 A에서 백업 JSON을 불러온다. 업로드만으로 상태가 바뀌지 않는지 확인하고, 미리보기에서 Finding별 적용/건너뛰기를 사용한다.
8. 대상 B를 선택해 검사한 뒤 A의 백업을 불러온다. 대상 문맥 불일치로 차단되어야 하며, 일부 Finding도 적용되면 안 된다.
9. 대상 A로 돌아가 같은 코드를 다시 검사한다. 새 검사 확인을 취소했을 때 기존 기록이 유지되는지, 승인 후에는 새 검사 상태가 시작되는지 확인한다.
10. 결과 지우기를 취소하거나 확정해 각 동작이 예상대로 처리되는지 확인한다.
11. Safari의 실제 페이지 확대를 200%로 맞춰 검사 시작, 결과 목록/상세, 검토·메모, 다운로드와 복원 미리보기를 확인한다. 화면 크기와 실제로 확인한 배율을 결과 문서에 적는다.
12. 키보드만 사용해 Tab/Shift+Tab, Enter/Space, Escape, 선택 상자, Finding, 메모, 파일 선택, 복원 적용/취소를 시도한다.
13. VoiceOver 검수는 실제 VoiceOver를 실행했을 때만 결과를 기록한다. 사용하지 않았다면 `NOT_TESTED`로 둔다.
14. iOS Safari는 실제 iPhone/iPad에서 확인하지 않았다면 별도 `NOT_TESTED`로 둔다.

같은 문맥의 JSON 복원을 확인할 때는 백업과 같은 대상을 선택하고 새 검사를 완료한 다음 백업을 불러온다. Finding ID와 주요 메타데이터가 일치해야 한다. 일치하더라도 코드 스냅샷이 같거나 과거 보안 검토가 현재 코드에도 유효하다는 뜻은 아니다. 기존 기록을 덮어쓸 경우 확인 대화상자를 검토하고, 각 Finding을 직접 적용한다.

## 5. Safari 200% 페이지 확대

Safari의 페이지 확대를 실제로 200%로 설정한다. 예를 들어 Safari의 `보기 > 확대` 메뉴 또는 웹사이트별 페이지 확대 설정을 사용할 수 있다. `Command + 0`은 확대 초기화에 사용되므로 200% 확인 중에는 누르지 않는다. 브라우저 창 크기만 줄인 결과를 실제 확대와 동일하게 기록하지 않는다.

다음 항목의 잘림, 겹침, 수평 스크롤, 포커스 가림 및 작업 완료 가능 여부를 확인한다.

- 검사 대상/규칙 선택, 토큰 입력, 검사 실행
- Finding 목록과 선택 Finding 상세
- 검토 상태와 분석가 메모
- Markdown/JSON 다운로드 버튼과 민감정보 확인
- JSON 파일 선택, 복원 미리보기 및 Finding별 적용

정확한 배율을 확인할 수 없는 경우 관찰 내용에 그 제한을 적고 해당 항목을 `NOT_TESTED`로 둔다.

## 6. 키보드 및 VoiceOver

macOS Safari는 시스템의 키보드 탐색 설정에 따라 Tab 이동 범위가 달라질 수 있다. Tab이 링크/버튼으로 이동하지 않으면 macOS의 키보드 탐색 설정을 확인하고 검수표에 사용한 설정을 기록한다. 파일 선택은 운영체제 네이티브 대화상자이므로 파일 선택 후 브라우저로 포커스가 돌아오는지도 살핀다.

VoiceOver는 실제로 켜고 사용한 검수자만 결과를 작성한다. 랜드마크, 제목, 입력/버튼 이름, 상태 메시지, Finding 선택, 복원 차단/성공 안내를 확인한다.

## 7. 종료와 정리

검수가 끝나면 실행 터미널에서 `Ctrl+C`를 누른다. QA 스크립트는 자식 프로세스 그룹을 종료하고 해당 실행에서 만든 임시 프로젝트와 임시 규칙 폴더만 정리한다. 이미 Safari에서 다운로드한 보고서/백업은 사용자의 다운로드 폴더에 남으며 스크립트가 삭제하지 않는다. 이를 보관할지 직접 결정한다.

## 8. 결과 기록

검수 일자, macOS/Safari 버전, 해상도, 페이지 확대, 검수자, 사용 대상, 항목별 `PASS / FAIL / NOT_TESTED`, 관찰 및 증거를 다음 문서에 기록한다.

`docs/phase8h-safari-user-acceptance-results.md`
