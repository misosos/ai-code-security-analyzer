# Phase 3C-3: Analyst Review 파일럿 및 정보 밀도 기준선

## 목적과 기준선

이 단계는 `scan --format review`의 실제 합성 출력량을 재현 가능하게 측정하고, 향후 소규모 형성적 사용자 평가를 준비한다. 출력 길이는 정보량 지표일 뿐 이해도나 사용성 점수가 아니다.

- 측정 기준 커밋: `c8fff609b8ab04093b193e6192bf58249cd3001e`
- 입력: 고정된 합성 Semgrep 결과 및 고정된 로컬 규칙 선언
- 화면: taint, pattern, partial, failed(timeout), zero findings
- 재현: `uv run python tests/review_usability_examples.py --case all`
- 지표: `uv run python tests/review_usability_examples.py --case all --metrics`
- 재현기는 Semgrep scan, LLM, 네트워크 요청을 수행하지 않는다.

Metrics 모드는 화면 문자열에서 줄·바이트·섹션별 표시 항목·위치를 계산한다. claim 수는 Gate 전체 claim 수가 아니라 화면에 실제 표시된 항목 수다. 카드별 줄 수는 카드 제목부터 다음 카드 직전 또는 출력 끝까지 세며, 카드 사이 빈 줄은 다음 카드 경계에 포함될 수 있다. 고정 문구 반복 집계는 스크립트에 명시된 정확한 문장만 대상으로 한다. 생략 수는 출력의 명시적 생략 문구에서만 읽는다.

모든 화면에서 고정 반복 문장 집계는 0이었다. 한 Finding씩인 고정 예시이므로 여러 카드에서 반복될 문구의 누적량은 측정하지 않는다. 출력 생략 사례는 이 다섯 기준 화면에 없으며 생략 0건은 재현 출력에서 확인한 값이다. 생략 경로 자체의 상한 회귀는 기존 review 테스트가 검증한다.

### Pattern 화면 수동 검토

실제 기준선 출력에서 일반 pattern 카드에는 지원된 매치 보고 1개, 제한된 claim 10개, 분석가 작업 3개가 표시됐다. 제한 claim 중 8개는 연결된 taint 근거 부재 때문에 taint 규칙/Source·Sink 선언/위치/trace/Sanitizer 매치 관련 내용을 제한한다. Sanitizer 효과와 취약점 확정은 별도의 미지원 주장으로 남는다. 이 화면은 일반 pattern을 taint 흐름으로 승격하지는 않지만, pattern 검토자가 당장 필요로 하지 않을 수 있는 taint 관련 제한 설명이 길다.

**개선 후보(가설):** 후속 실제 참가자 평가에서 이 항목이 핵심 매치와 다음 확인 작업을 가린다는 증거가 나오면, 표시 계층에서 taint 전용 제한을 접힌 “추가 근거 상태” 묶음으로 표현하는 방안을 검토한다. Gate, Summary, Consumer의 claim·reason·provenance는 삭제하거나 축약하지 않는다. 이번 Phase에서는 생산 화면을 변경하지 않았다. 이 과밀이 사용자 오해를 일으켰다는 관찰 자료는 아직 없다.

## 질문지와 채점표 검토

Phase 3C-2의 [참가자용 11문항](phase3c2-participant-questionnaire.md)과 [진행자용 채점표](phase3c2-scoring-key.md)를 재사용한다. 질문지와 채점표는 1–11번으로 일대일 대응하며 문항당 0–2점, 최대 22점 계산이 일치한다. N/A는 응답 건너뜀으로 분모에서 제외하도록 되어 있다. 질문은 Finding/확정 취약점, severity/검증 상태, taint 의미, Source 위치, trace 부재, partial, zero findings, checklist, 구조 검증, 실패 카드, pattern과 taint의 차이를 다룬다.

문항은 답을 자유롭게 설명하도록 하고 채점표를 참가자에게 보이지 않게 하므로 정답을 직접 제시하지 않는다. 참가자는 재현된 전체 화면을 먼저 읽도록 안내된다. 일부 질문은 화면 발췌의 표현을 다시 언급하지만 이는 이해 확인을 위한 참조다. 이번 검토에서 문항/채점표 불일치는 발견하지 않아 내용을 수정하지 않았다. 질문지 버전은 Phase 3C-2 자료 그대로다.

## 소규모 형성적 파일럿 진행 절차

1. 진행자는 평가 목적, 합성 자료만 사용한다는 점, 익명 기록, 참여 선택권을 설명한다.
2. 위 재현 명령으로 화면을 생성해 참가자에게 해당 화면 전체를 보여준다. 코드·실제 프로젝트 자료는 제공하지 않는다.
3. 참가자는 채점표 없이 참가자용 질문에 답한다. 진행자는 정답을 알려주거나 답을 유도하지 않는다.
4. 진행자는 문항별 답변 누락, 해석 오류 유형, 이해하기 어려운 문구, 참가자 제안만 익명 코드로 기록한다.
5. 응답 후 진행자만 채점표를 사용해 각 문항을 채점하고 N/A를 분리한다.
6. 기록에 실제 코드, 조직·사건 정보, 개인 식별정보가 들어가지 않았는지 검토한 뒤 오해 패턴과 후속 개선 후보를 정리한다.

보안 입문자와 기본 정적 분석 경험 개발자를 포함하는 구성을 고려할 수 있다. 실제 모집이나 참가자 수는 정하지 않았고 이번 Phase에서 사람 평가를 실행하지 않았다. 이 파일럿은 형성적 문제 발견용이며 통계적 효과를 입증하지 않는다.

## 비식별 기록 및 분석 정책

빈 기록 양식은 [파일럿 결과 템플릿](phase3c3-pilot-results-template.md)에 있다. 이름, 이메일, 전화번호, 회사/팀, 계정, 실제 코드, 실제 사건은 기록하지 않는다. 답변 자유 서술은 민감정보가 들어갈 수 있으므로 보관 전에 검토·삭제 또는 비식별화한다. 실제 참가자 기록은 기본적으로 저장소에 커밋하지 않는다.

응답이 확보된 뒤에만 응답 가능 문항 수, 문항별 정답 수/비율, 총점, N/A, 오해 유형, 화면별 어려움 위치를 집계한다. 소수 참가자의 결과를 전체 사용자 집단으로 일반화하지 않는다. 다른 참가자가 다른 화면을 보았다면 조건 차이를 함께 기록한다. 비교 가능한 사전·사후 또는 화면 버전 자료가 없으면 개선 효과나 만족도 향상을 주장하지 않는다.

## 결과 범주와 상태

- **자동 측정:** 위 표의 렌더링 기반 수치와 기존 자동 회귀. 이는 사용성 점수가 아니다.
- **수동 전문가 검토:** 기준선 pattern 화면의 제한 claim 밀도와 표시 개선 후보를 확인했다. 이는 참가자 관찰이 아니다.
- **사람 대상 파일럿:** `NOT_TESTED`. 참가자 응답, 이해도 점수, 만족도 및 응답 시간은 없다.

## 보안 및 의미 불변

합성 예시의 원본 메시지와 코드 줄에는 canary가 있지만 renderer 출력과 metrics JSON에는 나타나지 않는다. Review View는 기존 Gate/Consumer의 허용·제한 결과를 그대로 사용한다. Finding status, 공개 CLI/JSON, 분석 근거와 checklist 동작을 변경하지 않았다. 지원되지 않은 claim은 화면에서 승격되지 않는다. 이 지표는 문장 의미 전체의 안전성, 실제 코드에서의 정보 밀도, 대량 결과의 가독성 또는 사람의 이해도를 증명하지 않는다.
