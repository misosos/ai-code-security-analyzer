# ER-D8 Evidence Gap 평가

## 실제 합성 실행

Semgrep OSS 1.182.1, 신뢰된 로컬 baseline 사본, 격리 FastAPI와 Chromium으로 실행했다. 각 사례는 독립 서버와 임시 대상에서 실행됐다.

| 사례 | 실제 관찰 및 Map | 제한 |
| --- | --- | --- |
| A 정상 A/B → A/C | 기준만·양쪽·현재만 각 1건, 소스 미수집과 범위·로딩 규칙 미검증 표시 | B의 해결과 변경 원인은 판단하지 않음 |
| B Ignore | B의 경로 제외 관찰, `SUPPORTED`, 현재 `PARTIAL`, 전체 `INCOMPARABLE`, 경로 확인 제안 | 공개 Evaluation은 구체적 제외 사유를 전달하지 않음 |
| C 동일 바이트 | 완료된 독립 Run에서 선택된 단일 사본 바이트 동일 표시 | 로딩된 전체 규칙과 소스 동일성은 미검증 |
| D 주석 변경 | 격리된 선택 규칙 사본의 주석만 추가, Finding ID는 같고 바이트는 다름 | 의미상 규칙 동작 변경이나 원인을 확정하지 않음 |
| E 옵션 OFF | 기존 v2 조사에서 규칙 바이트 비교를 요청하지 않았다고 표시 | 서버의 `UNVERIFIED` 응답으로 꾸미지 않음 |
| F 해제·오래된 응답 | 해제 후 Map 제거, 지연된 Rule Bytes 응답이 기준 해제 후 Map을 복구하지 못함. 합성 시계로 클라이언트 표시 만료 후 Map 제거 확인 | 실제 서버의 15분 경과와 사용자 판단은 별도 검증 필요 |

A/C, D, E는 `D8_GAP_CASE=same`, `comment`, `off`로 격리된 실제 브라우저 하네스를 각각 실행했다. B는 기본 실제 조사 E2E에서 실행했다. Mock 응답으로는 누락·잘못된 계약·중복 ID·Partition 불일치·모드 혼합·부분 검사에서 잘못된 동일성 주장 및 0 Finding을 검증했다.

## 해석

기존 화면이 제공하던 Finding 범주와 조사 결과에 전체 증거의 출처·공백과 Finding별 경로 관찰, 해당 후속 작업을 연결했다. Map은 취약점 해결, 소스 변경 원인, 전체 규칙 적용 또는 안전성을 자동 판정하지 않는다. 사람 대상 비교 연구를 수행하지 않았으므로 이해도, 판단 정확도와 시간 개선은 확인되지 않았다.
