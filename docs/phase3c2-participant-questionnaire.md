# Analyst Review 이해도 질문지 — 참가자용

## 진행 안내

아래는 실제 프로젝트나 비밀정보가 아닌 합성 입력으로 만든 Analyst Review 화면의 발췌다. 문항에 답하기 전에 진행자가 생성한 **전체 `--format review` 화면**을 읽는다. 문구를 암기하기보다 화면에서 확인한 내용으로 답한다. 각 문항은 정답을 고르거나 한두 문장으로 설명한다. 진행자는 정답표를 참가자에게 보이지 않는다.

진행자 재현 명령: `uv run python tests/review_usability_examples.py --case all`. 이 명령은 taint, pattern, partial, failed, zero 합성 화면을 실제 Review View renderer로 출력한다. Semgrep scan이나 모델 추론은 실행하지 않는다.

이 평가는 사람을 평가하지 않고 화면 전달을 평가한다. 이름, 이메일, 소속, 업무 코드, 실제 조사 자료는 수집하지 않는다. 답변은 익명 코드와 참가자 경험 범주(보안 입문자 / 정적 분석 경험 개발자 / 보안 분석 경험자)만 기록한다. 참가하지 않아도 불이익이 없다.

## 화면 발췌 A — 완료된 taint 검토 후보

```text
검사 상태: 정상 완료
검사 완료: 예
검토 대상: 1건 (취약점 확정 수가 아님)
도구 심각도 분류별 검토 대상: critical 0건, high 1건, medium 0건, low 0건, info 0건

요약: taint 규칙 매치 검토
Semgrep 심각도 분류: high (실제 악용 가능성 판정은 아님)
검증 상태: 미검증 후보 (취약점·오탐 모두 미확정)
탐지 유형: taint 규칙 (정의된 입력 흐름을 검사하는 규칙)
근거 검증: 통과 (구조적 연결만 확인; 취약점 검증을 뜻하지 않음)
확인된 사실:
- Semgrep이 신뢰된 taint 규칙에 따른 매치를 보고했습니다.
- 신뢰된 규칙에 Source 패턴이 선언되어 있습니다.
- 신뢰된 규칙에 Sink 패턴이 선언되어 있습니다.
확인되지 않았거나 이 분석에서 지원하지 않는 내용:
- 실제 Source 위치 식별 [현재 자료에서 확인 불가]
- Sink 인자 위치 식별 [현재 자료에서 확인 불가]
- 전체 데이터 흐름 경로 제공 [현재 자료에서 확인 불가]
  구조화된 데이터 흐름 trace가 제공되지 않았습니다. 흐름이 없다는 뜻은 아닙니다.
- Sanitizer 효과 검증 [이 분석에서 지원하지 않는 판단]
- 취약점 확정 [이 분석에서 지원하지 않는 판단]
분석가 검토 항목:
1. 실제 입력 출처를 코드에서 확인
2. 위험 함수에 전달되는 값 확인
3. 입력 검증과 정제 로직 확인
```

## 화면 발췌 B — 일부 경로가 생략된 부분 검사

```text
검사 상태: 부분 검사
검사 완료: 아니요
검토 대상: 1건 (취약점 확정 수가 아님)
주의: 일부 경로 또는 규칙이 누락될 수 있어 전체 검사가 완료되지 않았습니다.
검사 안내: 일부 경로를 건너뜀
확인된 사실:
- Semgrep이 해당 규칙 매치를 보고했습니다.
확인되지 않았거나 이 분석에서 지원하지 않는 내용:
- 신뢰된 taint 규칙 매치 보고 [근거 부족]
  검사가 일부만 완료됐습니다. 전체 검사가 완료되지 않았습니다.
```

## 화면 발췌 C — 정상 완료, Finding 0건

```text
검사 상태: 정상 완료
검사 완료: 예
검토 대상: 0건 (취약점 확정 수가 아님)
해석 제한: 탐지 0건도 대상 코드가 안전하다는 뜻은 아닙니다.
```

## 화면 발췌 D — 일반 pattern 매치

```text
탐지 유형: 일반 패턴
확인된 사실:
- Semgrep이 해당 규칙 매치를 보고했습니다.
확인되지 않았거나 이 분석에서 지원하지 않는 내용:
- 신뢰된 taint 규칙 매치 보고 [현재 자료에서 확인 불가]
분석가 검토 항목:
1. 탐지된 패턴이 실제 코드인지 확인
```

## 질문

1. 화면 A의 검토 대상 1건은 무엇을 세나요? 이것만으로 확정 취약점이 1건이라고 말할 수 있나요? 이유를 적어 주세요.

2. 화면 A의 `high`와 `미검증 후보`는 각각 무엇을 뜻하나요? 둘 중 어느 하나가 실제 악용 가능성을 확정하나요?

3. 화면 A의 taint 규칙 매치가 확인해 주는 사실은 무엇인가요? 실제 입력 위치와 완전한 입력 흐름까지 확인됐나요?

4. `실제 Source 위치 식별 [현재 자료에서 확인 불가]`를 어떻게 해석해야 하나요? 입력 Source가 존재하지 않는다는 뜻인가요?

5. 화면 A에서 구조화 trace가 제공되지 않았다는 설명은 무엇을 뜻하나요? 데이터 흐름이 없거나 오탐이라고 결론 내릴 수 있나요?

6. 화면 B에서 `검사 완료: 아니요`와 일부 규칙 매치가 함께 보입니다. 이 상태에서 전체 대상의 검사 범위나 미탐 여부를 어떻게 설명하겠습니까?

7. 화면 C는 정상 완료됐고 Finding이 0건입니다. 이 결과로 대상 코드가 안전하다고 결론 내릴 수 있나요? 화면에서 근거를 찾아 답해 주세요.

8. 화면 A의 분석가 검토 항목은 이미 완료된 보안 검증인가요, 다음에 사람이 확인할 작업인가요? 체크리스트가 있다고 어떤 보안 결론을 낼 수 있나요?

9. 화면 A에서 `근거 검증: 통과`라고 되어 있습니다. 이는 코드의 취약점 의미가 맞다고 검증된 것인가요, 다른 종류의 검증인가요?

10. 만약 카드가 `근거 검증: 실패`를 표시하고 확인된 사실을 숨긴다면, 그 카드의 Finding을 확인된 사실로 사용해도 되나요? 다음으로 무엇을 해야 한다고 이해하나요?

11. 화면 D의 일반 pattern 매치는 화면 A의 taint 규칙 매치와 어떤 점이 다릅니까? 화면 D에서 Source→Sink 흐름을 확인했다고 말할 수 있나요?

답변은 평가 목적에만 사용한다. 이름, 이메일, 실제 업무·코드 정보는 제공하지 않아도 된다.
